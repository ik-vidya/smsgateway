# Административный веб-UI

Встроенный веб-интерфейс для управления smsgateway. Работает на
отдельном порту (`WEBUI_ADDR`, по умолчанию `127.0.0.1:8081`),
включается через `WEBUI_ENABLED=true`.

## Стек

- `html/template` — шаблоны встроены в бинарник через `//go:embed`.
- Bootstrap 5.2.3 — вёрстка; хранится локально в
  `internal/webui/static/vendor/bootstrap/`, скачивается через
  `make fetch` и коммитится в репозиторий.
- htmx 4.0 — динамика без полной перезагрузки; локально в
  `internal/webui/static/vendor/htmx/`.
- `go-i18n/v2` — локализация (ru/lv/en).
- Нативный `EventSource` (SSE) — для живых потоков логов и портов.

CSP: `default-src 'self'` (никаких CDN). CSRF: `SameSite=Lax`
на cookie + проверка `Origin`/`Referer` в middleware для
не-GET запросов.

## Авторизация

**Пока не реализована** (`WEBUI_AUTH_MODE=none`). Страница `/setup`
имеет привилегированный доступ (открывает порты, правит `.env`,
перезапускает сервис) — это осознанное решение для сценария
«админ за ssh/локально». OIDC (этап B4) отложен до готовности
библиотеки.

Если Web UI выставлен в сеть (`WEBUI_ADDR=0.0.0.0:8081`) —
обязательно ограничить доступ firewall'ом или reverse proxy с
basic auth. Это ответственность администратора.

## Страницы

### `/` — Dashboard

Состояние сервиса и модема.

- **Модем**: порт, профиль, производитель, модель, прошивка,
  IMEI, сигнал (CSQ и dBm), статус регистрации. Если модем не
  сконфигурирован (`SERIAL_PORT=none`) — плашка «не
  сконфигурирован».
- **База данных**: путь, health, uptime, статус Gammu file backend.
- **Счётчики**: количество сообщений по статусам (queued, sending,
  sent, delivered, failed, sent_no_dr, received).

### `/inbox` и `/outbox`

Списки сообщений с фильтрами и пагинацией.

- **Фильтры**: номер (подстрока), статус, дата с/по
  (`<input type="date">`).
- **Пагинация**: limit по умолчанию 50, максимум 500.
- **htmx**: форма фильтров и ссылки пагинации работают через
  `hx-get` + `hx-target="#messages-table"` + `hx-push-url`. Сервер
  по заголовку `HX-Request` отдаёт либо полный layout, либо только
  фрагмент `messages-table` — progressive enhancement, работает и
  без htmx.
- **Текст SMS**: `<details>/<summary>` для раскрытия полного
  текста — нативный HTML, без JS.

### `/compose`

Форма отправки SMS. POST `/compose` ставит сообщение в очередь
через `Service.EnqueueOutgoing` и редиректит на `/compose?sent=1`.

Валидация на сервере: `to` (E.164, `+` + 5-20 символов), `text`
(непустой, до 4000 символов).

### `/logs`

Live-поток логов через SSE. Подключается к `/logs/stream`,
рисует записи в DOM (лимит 2000 строк, старые вытесняются).

Управление:
- фильтр по уровню (All/Info/Warn/Error) — новые записи ниже
  уровня не отображаются;
- пауза — записи продолжают копиться, но список не прокручивается;
- очистка — очищает DOM, поток продолжается;
- автопрокрутка вниз отключается, если пользователь прокрутил
  вверх (не дёргается, пока не вернётся к хвосту).

При переполнении канала подписчика сервер шлёт событие `warning`
с числом пропущенных записей — клиент пишет в консоль.

### `/setup`

Настройка модема. Ключевая страница для сценария «инженер без
клавиатуры»: подключил модем к USB, зашёл в браузер, нажал пару
кнопок.

**Поток:**

1. Страница подключается к `/setup/ports/stream` (SSE) и в
   реальном времени показывает список доступных портов из
   `/dev/serial/by-id/` (fallback `/dev/ttyUSB*`, `/dev/ttyACM*`).
   Обновляется автоматически при подключении/отключении модема.
2. У каждого порта — кнопка **«Проверить»** (POST `/setup/probe`):
   сервер открывает порт, шлёт `AT`, `ATE0`, `AT+CGMI`,
   `AT+CGMM`, `AT+CGMR`, `AT+CGSN` и возвращает JSON с моделью и
   IMEI. Если модем не отвечает — показывается текст ошибки.
3. При успехе появляется кнопка **«Сохранить и перезапустить»**
   (POST `/setup/save`): сервер пишет `SERIAL_PORT` в `.env`
   (сохраняя комментарии и остальные переменные), возвращает 200
   и в фоне шлёт `SIGHUP` самому себе. Страница показывает
   «Сохранено. Сервис перезапускается…» и через 5 секунд
   перезагружается на `/setup` — уже с новым текущим портом.
4. Кнопка **«Отправить тестовую SMS»** (POST `/setup/test`)
   доступна, если заданы и `SERIAL_PORT`, и `SELF_NUMBER`. Вызов
   синхронный: сервер ждёт терминального статуса (доставлено/
   ошибка) или таймаута `TEST_SMS_TIMEOUT`. Результат
   показывается цветным alert и **дублируется в Telegram** через
   `Notifier` (если Telegram включён).

**Валидация порта** — whitelist префиксов:
`/dev/serial/by-id/`, `/dev/serial/by-path/`, `/dev/ttyUSB*`,
`/dev/ttyACM*` + проверка существования файла. Это защита от
опечатки (`/dev/ttyS0` — консоль, `/dev/mem` — память, и т.п.).

**Rate limit**: probe — не чаще 100 мс, только один за раз.

### `/lang/{code}`

Установка cookie `lang` и редирект на главную. Определение языка:
`?lang=xx` → cookie → `Accept-Language` → `WEBUI_DEFAULT_LANG`.

## Hot-reload через SIGHUP

Механизм, который использует `/setup/save` для перезапуска с
новым портом без остановки сервиса (systemd не замечает рестарт):

1. `handleSetupSave` пишет `SERIAL_PORT` в `.env`, отвечает 200 и
   в фоне шлёт `SIGHUP` процессу.
2. `cmd/smsgateway/main.go` ловит `SIGHUP`:
   - отменяет контекст (останавливаются URC-цикл, отправка,
     pending references, gammu watcher, HTTP API, Web UI);
   - дожидается завершения сервисных горутин;
   - вызывает `apiServer.Shutdown` и `webServer.Shutdown` —
     освобождает порты;
   - вызывает `cleanup()` — закрывает notifier, БД, модем через
     `sync.Once`;
   - делает `syscall.Exec("/proc/self/exe", os.Args, os.Environ())`
     — заменяет образ процесса. PID сохраняется, systemd не
     замечает.
3. Новый образ читает обновлённый `.env` и стартует с новым
   `SERIAL_PORT`.

Если `syscall.Exec` провалится (бинарник удалён или перемещён) —
в логе будет `syscall.Exec err=...`, сервис завершится. При
`Restart=always` в systemd перезапустится штатно.

Тот же механизм можно использовать вручную:

```bash
kill -HUP $(pgrep -f 'smsgateway.*--config')
```

## Запуск

```
WEBUI_ENABLED=true
WEBUI_ADDR=127.0.0.1:8081
WEBUI_DEFAULT_LANG=ru
WEBUI_SUPPORTED_LANGS=ru,lv,en
WEBUI_AUTH_MODE=none
```

```bash
./bin/smsgateway --config .env
# Web UI слушает 127.0.0.1:8081
```

## Ограничения

- **Авторизация не реализована**. OIDC — отдельный этап.
- **`WriteTimeout=0`** у webui-сервера — SSE-потоки живут дольше
  обычных запросов. Защита от «медленного клиента» (slowloris) не
  работает; `ReadHeaderTimeout` и `ReadTimeout` при этом
  остаются. Для доверенной сети — приемлемо.
- **`/setup` не блокируется при уже настроенном сервисе**:
  страница всегда доступна, повторное сохранение порта
  перезапустит сервис.
- **Flash SMS** (`f` в расширении OUT-файла Gammu) не
  поддерживается на уровне `pdu.Build` — отправляется как
  обычное SMS, в лог пишется warning.
- **htmx 4.0 SSE extension** не используется — нативный
  `EventSource` даёт полный контроль над фильтрацией, скроллом и
  лимитом DOM.

## Что не вошло

- **OIDC** (B4) — отложен до готовности библиотеки.
- **Мультимодемность в UI** — сейчас один процесс = один модем.
  Запуск нескольких инстансов — через systemd unit-шаблоны с
  разными `.env`.
- **Live-обновление dashboard** — счётчики обновляются по F5.
  Если понадобится, добавим SSE-канал `/dashboard/stream`.
